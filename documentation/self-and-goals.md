# 自我档案与目标裁决

## 1 默认优化的偏差

语言模型优化的是「这条消息的效果」：让对方舒服、让对话继续、让气氛变好。这个目标在多数场景下是对的，在恋爱场景里经常是错的。

因为恋爱场景的诉求不是"效果好"，是"我要的东西"。同一段对话，三种诉求三种正解：

| 诉求 | 正解 |
|---|---|
| 想挽回 | 低压力、给台阶、留门 |
| 想看清她怎么想 | 能问出实情、不带审问感 |
| 想体面结束 | 把话说完整、不留钩子 |

默认优化会稳定地给出第一种，因为它在"效果"这一维度上最高。这不是模型不聪明，是**目标函数缺了一项**。

自我档案就是补上这一项：把用户的方向显式写下来，让它参与甚至主导排序。

## 2 为什么分「她」和「我」两份

对她的档案按关系槽位分（`couple_early` / `friend` / `work`），因为同一个人在不同关系里需要不同信息。

自我档案**全局只有一份**，因为"我是谁"不随对象变。同一个人的底线、短板、说话习惯，对女朋友和对同事都成立。

唯一的例外是**目标**：目标挂在槽位上，因为"我想跟这段关系走多远"是特定于对象的。所以 `data/self.json` 全局，`goals` 放在每个 `data/profile/{slot}.json` 里。

这个拆分有个副作用：换一个新对象时，自我档案可以直接复用，只需要建新槽位、写新目标。这是有意的——你不需要重新交代自己一遍。

## 3 硬与软：为什么不用权重

目标有两种用法：影响排序，或者直接过滤。

一开始想的是全部进权重：`goal_fit` 加上目标匹配度。但很快遇到一个问题——有些目标是**不可交易**的。

"不接受异地"不是一个"降低权重"的偏好。如果候选里出现"我下个月搬过去"，它不该排在第三位，它不该出现。给一个百分比匹配度，意味着某条候选可以"部分符合底线"，这没有意义。

所以分两类：

- **硬目标 + 底线 + 短板** → 过滤。命中 `forbid` 词直接删，不参与排序。
- **软目标** → 进打分。影响 `goal_fit`，不删候选。

判据很简单：**能不能被交换？** 能被交换的（"想三个月内明确"可以和"这周先别催"交换）进打分；不能被交换的（"不接受异地"）做过滤。

## 4 为什么用字面匹配，不用语义

守门用的是 `if kw in text`，纯字面。这看起来很粗糙，但比语义匹配可靠。

语义匹配的问题是**不可预测**。用户写"我不接受异地"，模型去判断"我下个月搬过去陪你"是否语义相关——大多数时候对，偶尔会漏，而漏的那次恰好是最需要拦的那次。字面匹配不会漏，只会误伤，误伤可以被用户看到并修正。

代价是用户必须自己写触发词：

```bash
--forbid 搬过去 去你那边 换工作 辞职
```

这是有意的负担。写触发词的过程本身就是一次澄清：你到底在防什么。写不出来，说明这条底线还太模糊，模糊的底线拦不住任何东西。

配了触发词之后，报错也很直接：

```
[底线 m1] 出现「搬过去」——你写过：不接受异地，不为了恋爱换城市
```

用户一看就知道是哪条、为什么。

## 5 目标会僵化

目标写下来之后，最大的风险不是写错，是**写对了但没改**。

```
三个月后：目标是 "advance"，但关系已经冷了一个月
→ 模型仍然每次都想往前推
→ 每次候选都偏急
→ 用户觉得"它不懂现在的状况"
```

这不是模型的错，是档案过期了。所以目标必须能被关掉：

```bash
goal done --slot couple_early --ids g1   # 完成了
goal drop --slot couple_early --ids g1   # 放弃了
```

同时脚本在活动目标超过四条时会警告，因为超过四条之后模型会在它们之间摇摆，每条照顾一点、每条都不深。

**建议的复核节奏**：每次阶段变化时清一遍目标。阶段变了目标多半也要变，两者不同步是最常见的失效原因。

## 6 与阶段的关系

阶段和目标都能约束候选，但管的东西不同：

```
阶段 → 手段（这一句能不能说、能有多长、能给多少细节）
目标 → 方向（说了之后往哪走）
```

冲突时的规则是**阶段优先**：

```
目标：三个月内明确关系（想 advance）
阶段：repairing（禁 advance）
→ 阶段赢。正确输出不是"放弃目标"，而是"这次不说，先处理上次那件事"
```

这条规则有一个例外：目标是 `exit` 时，阶段闸门放宽。理由在 `stages.md` 第 2 节。

## 7 自我档案更敏感

她的档案记的是别人，自我档案记的是自己，包括不会对任何人说的部分：底线、软肋、反复犯的错、真正在意的东西。

所以隐私处理要更严：

- 存在本地 `data/self.json`，明文，用户可以直接改
- `data/` 在 `.gitignore`，不会进版本库
- **不带进公开仓库的任何示例**。文档里的例子都是虚构的通用示例，不是真实用户数据
- `export` 导出的是 Markdown，方便用户自己备份或带走；`forget` 单条删除

一条额外的设计约束：**不要把自我档案朗读给用户看**。它存在是为了让建议更准，不是为了展示"我记住了你是个什么样的人"。后者会让人觉得被分析，而不是被帮忙。

## 8 已知局限

- **自我认知本身可能不准。** 人对自己行为的描述经常和行为不一致。统计过的风格卡比自述可靠，所以两者冲突时以风格卡为准（见 `references/self.md` 第 8 节）。
- **守门只查字面。** 语义层面的越界（比如没有出现"搬过去"但意思还是要搬）拦不住，靠提示词规则兜底。
- **目标不改判断。** 目标是 `advance` 不会让 `danger` 变低。判断层看的是当下这段对话，目标看的是长期方向，两者不能互相污染。
- **没有校准集。** 硬目标和触发词的效果依赖用户写得准不准，没有任何自动校准机制。
