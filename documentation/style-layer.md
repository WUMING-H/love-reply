# 风格层

这一层决定输出是「一个正常人会怎么回」还是「你会怎么回」。它是本项目区别于同类工具的地方，也是最多人做错的地方——错法高度一致：把「像人」当成了目标。

---

## 一、目标定错了会怎样

「让 AI 模仿我说话」这个需求，几乎所有人的第一反应都是让模型去总结风格：「我说话比较直接，爱用短句，偶尔开玩笑」。然后把它写进提示词。

这个做法有三个问题，每一个都致命：

**一、总结不可执行。** 「比较直接」是一个形容词，模型无法据此判断某句话够不够直接。它只能生成一段它认为直接的话，而那通常是它见过的所有「直接」的平均值。

**二、总结没有数值。** 你说「爱用短句」，模型理解成 30 字以内；你的实际中位数是 11 字。差三倍，但双方都以为说清楚了。

**三、目标无法验收。** 「像人」的验收标准是「读起来自然」——任何一段通顺的话都通过。于是这一层永远无法判断自己有没有进步，也无法回归测试。

正确的目标是**「像你」**，而它有一个可操作的定义：**盲测猜不出来**。把你最近发的 5 条和它写的 5 条混在一起，让熟悉你的人挑出哪些不是你写的。猜中率接近 50%（随机水平）才算通过。

这个定义把主观问题变成了一个可以反复运行的实验。所有后续设计都是为了让它成立。

---

## 二、三个设计决定

### 1 长度是第一信号，不是用词

先看两组真实数据：

| 指标 | 真人微信（中文） | 大模型直出 |
| --- | --- | --- |
| 中位字数 | 8–18 | 40–70 |
| ≤6 字消息占比 | 40%–70% | 接近 0 |
| 句末句号率 | 0–10% | 60%–90% |
| 开场白 | 通常没有 | 「我理解你」「听起来」 |
| 收尾 | 通常没有 | 「希望这能帮到你」 |

差距最大的是长度分布和句号率，不是词汇。所以风格层的第一个动作顺序固定：

1. **切碎**——超过上限的长句拆成两三条，或用空格断开（这是微信的实际习惯，不是标点错误）。
2. **删句号**——句末的「。」几乎总是书面语残留。
3. **删开场白与收尾**——「我理解你的感受」这类前缀全删，直接说事。

做完这三步，即使一个词都没换，像的程度已经大幅提升。反之，只换词汇不动长度，写出来的是**另一个人穿着你的衣服**。

### 2 度量交给代码

模型数不出「你的句号率是 0.06」。让它估，它会给你 0.3 这种量级——因为它对「偶尔」的理解是文本层面的印象，不是统计。

而 0.06 和 0.3 之间的差别，正好就是「像」和「不像」的差别。所以 `scripts/style_tool.py` 的 `compute()` 用纯代码算，不调模型、不联网、不依赖第三方包。

计算项：

| 字段 | 定义 | 用途 |
| --- | --- | --- |
| `chars_p50` | 字数中位数 | 主长度基准 |
| `chars_p90` | 字数 90 分位 | 上限基准 |
| `chars_max` | 最长一条 | 判断语料是否混入长文 |
| `short_ratio` | ≤6 字消息占比 | 碎片化程度 |
| `terminal_period` | 以「。」结尾的比例 | 书面语残留强度 |
| `emoji_per_100` | 每百字 emoji 数 | 表情使用强度 |
| `exclaim_rate` | 含感叹号的消息占比 | 情绪外露强度 |
| `question_mark_rate` | 含问号的消息占比 | 互动倾向 |
| `particle_per_100` | 每百字语气助词数 | 口语化程度 |
| `high_risk_particle_per_100` | 每百字「呢啦呀嘛呗咯」数 | 撒娇 / 示弱倾向 |
| `latin_ratio` | 拉丁字母占比 | 中英混用程度 |

### 3 `avoid` 比 `strategy` 有用

风格卡里有两类内容：正面描述（`length` / `punctuation` / `anger` / `comfort` …）和负向禁用（`avoid`）。

实测结论：**起作用的是 `avoid`。**

模型很难执行「你要幽默」——它不知道幽默到什么程度算合适，于是要么不开玩笑，要么开一个不得体的玩笑。但「不许出现 emoji」是 100% 可执行的：出现了就是错，没出现就是对。

所以 `profile` 的主要工作是从语料反推「你从不做什么」：

| 观察到 | 推出的禁用项 |
| --- | --- |
| 语料里没有任何 emoji | 不用 emoji |
| 没有连续重复字（如「好好」） | 不用叠字 |
| 没有「呢啦呀嘛呗咯」 | 不用「呢、啦、呀」 |
| 没有波浪号 | 不用波浪号 |
| 句号率低于 10% | 不加句号 |
| 没有「哈哈」「笑死」类 | 不用「哈哈」 |

这是唯一一类既能自动生成、又能被严格执行的风格约束。风格卡的进步，主要是这张表变长变准的过程。

## 三、风格卡 schema

存放于 `data/style/{slot}.json`，`profile` 生成，也可手改。

```json
{
  "slot": "couple_early",
  "version": 3,
  "updated_at": "2026-11-10T15:02:11+08:00",
  "metrics": {
    "source_count": 128,
    "chars_p50": 11,
    "chars_p90": 28,
    "chars_max": 62,
    "short_ratio": 0.56,
    "emoji_per_100": 0.0,
    "terminal_period": 0.06,
    "exclaim_rate": 0.08,
    "question_mark_rate": 0.14,
    "particle_per_100": 2.1,
    "high_risk_particle_per_100": 0.0,
    "latin_ratio": 0.004
  },
  "strategy": {
    "length": "短，能五个字说完不写八个字",
    "punctuation": "几乎不用句号",
    "anger": "变短，不解释",
    "comfort": "先接情绪，不给方案",
    "apology": "认具体那件事，不铺陈",
    "humor": "自嘲，不调侃对方",
    "avoid": ["不用 emoji", "不加句号", "不用叠字", "不用「呢、啦、呀」"]
  },
  "samples": {
    "advance": ["周六 我过去接你"],
    "comfort": ["她那人事儿真多 你别往心里去"]
  },
  "ngram": ["行 是我没看到", "那我过去", "你先忙"]
}
```

几个字段的用意：

- **`version`** 每次 `profile` 自增。改坏了可以对比前后版本，不用凭记忆还原。
- **`strategy.anger` / `comfort` / `apology` / `humor`** 脚本**不猜**，留作人工或对话校准。这些是行为倾向，统计推不出来——「生气时变短」和「生气时变长讲道理」在数据上都能解释得通。
- **`samples`** 按场景存，每个场景最多 20 条。这是 few-shot 的来源，也是「改写过的话」的落点。
- **`ngram`** 高频 2–4 字片段，用于让模型感知语感，不直接进候选。

## 四、冷启动

没有语料时，五个问题能建出可用的 v0：

1. 一般连着发几条？每条多长？
2. 句末加句号吗？
3. 用 emoji 吗？最常用哪两个？
4. 生气时变长（讲道理）还是变短（冷处理）？
5. 安慰人是先讲道理，还是先接情绪？

第 4、5 问是脚本推不出来的，也是最能区分人的两项。v0 一定不准，这是预期内的；它只是让第一次使用不至于输出一段完全陌生的语气。

**冷启动不阻塞当次输出。** 先用安全默认出结果，末尾轻问一句「要不要校准」。首次使用就被要求填五个问题，多数人会直接关掉——这是产品问题，不是设计问题。

## 五、校验阈值

`check(text, card, strategy)` 的输出是 `{ok, length, target_range, problems}`，`problems` 是给人看的修改指令，不是评分。

长度上限**按策略分档**，因为不同策略天生长度不同。用一把尺子量所有候选，「给具体时间方案」这类必要长句会被 `minimal` 的上限全部误杀。

有卡时：

| 策略 | 上限 | 下限 |
| --- | --- | --- |
| `minimal` / `care` / `hold` | `max(p90 × 1.2, 18)` | `min(6, max(2, p50 × 0.4))` |
| `substantive` / `repair` | `max(p90 × 2.2, p50 × 3, 34)` | 同上 |
| `advance` / `auto` | `max(p90 × 1.6, p50 × 2.2, 24)` | 同上 |

无卡时用**绝对档位**，不套系数：

| 策略 | 上限 |
| --- | --- |
| `minimal` / `care` / `hold` | 16 |
| `advance` / `auto` | 26 |
| `repair` | 34 |
| `substantive` | 40 |

理由：无卡时的默认值（p50=12, p90=34）本身就是一个合理区间，不是这个人的统计。拿它套 2.2 倍会算出 74 字——等于没有上限。

**绝对下限的存在同样重要**：如果语料里全是「嗯」「行」「哦」，p90 会被压到 3，上限变成 18 也救不回来。这时宁可放宽，也不要让校验器逼着模型把信息删掉。

除长度外还检查：

- **术语与 AI 味黑名单**（`AI_SMELL`）：此外、总之、建议你、我理解你的感受、深呼吸、希望这能帮到你……命中即失败。
- **禁用项**：风格卡 `avoid` 里的每一条。

**连败两次就用未改写的版本。** 宁可不像，不要为像而失真——把「下周六下午两点」压成「周六见」是风格层的典型过度拟合：字数是像了，信息丢了。

## 六、反馈回流

三种反馈，价值递增：

| 用户说 | 记录为 | 效果 |
| --- | --- | --- |
| 「第 2 条」 | `chosen` | 只记偏好日志，不改进度 |
| 「太长了」「太软了」 | 口头 | 直接改阈值或 `strategy` 描述 |
| 「不像我，我会说 XX」 | `edited` | **进样本库**，下次作为 few-shot 参照 |

第三种是唯一能自动提升准确率的。原因很直接：点选只说明「三条里这条最好」，改写说明「差异在哪」——后者才是可学习的信号。

`feedback --kind edited` 会把用户改写后的句子按场景写入 `samples`，同场景保留最近 20 条。

```bash
python scripts/style_tool.py feedback --slot couple_early --kind edited \
  --ai "周六下午我去接你" --user "周六 我过去" --scene advance
```

## 七、为什么不微调

直觉上「500 条语料训一个小模型」更彻底，实际是陷阱：

- **数据量不够。** 500 条中文短消息训出来的模型，会同时学会你的口癖和一批噪声，输出是四不像。
- **改一次要重训。** 想调整「生气时该更短」，微调模型要重新准备数据、重新训练；风格卡改一个 JSON，立刻生效。
- **不可解释。** 微调后的模型为什么这么写，你永远不知道。风格卡里每一条都能追溯到具体统计或具体改写。
- **不可回滚。** 训练坏了就是坏了。`version` 字段让你随时退回上一版。

风格卡的上限低于微调，但在中文短消息这个任务上，风格卡能拿到的 80% 已经够用——因为剩下那 20% 是词汇层面的细微偏好，而用户对长度的敏感度远高于对词汇的敏感度。

---

## 八、按关系分槽位

`slot` 是一个字符串，常用值：`couple_early` / `couple_stable` / `friend` / `work`。

分了不是为了精细，是为了**防串味**。人对伴侣、对朋友、对同事是三种人：对伴侣会撒娇、用叠字、发短句；对同事会完整句子、加敬语、避免表情。混在一个卡里，统计出来是一个不存在的人。

第一次使用时通常只需要一个槽位——最常需要回消息的那段关系。等你在别的场景也觉得「不像我」时再加。

---

## 九、验收

改完风格层（阈值、`avoid` 规则、few-shot 组织方式）之后，跑一次盲测：

1. 从他最近的聊天里取 5 条真实消息。
2. 用相同情境让系统生成 5 条。
3. 混在一起，去掉来源标记，给一个熟悉他的人看。
4. 记录猜中率。

单次 10 条样本的统计意义很有限，但这个流程的价值不在数值，在于**它强迫你把「像不像」变成一个具体判断**。凭感觉说「还行」的时候，往往已经差得很远。
