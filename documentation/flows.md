# 判断与生成流程

这份文档展开 `SKILL.md` 里被压缩成表格的部分：七个问题各自的取值、判据、典型误判；七类动作的适用边界；三条候选的策略差异；以及输出为什么会是现在这个格式。

---

## 一、七个问题

### 1 `literal` — 这句话是不是纯字面

取值：`yes` / `no` / `unclear`。

中文的日常表达里，字面义和实际义分离是常态，不是例外。「没事」在九成语境里不是没事。「行吧」的「吧」是一个降调标记，表示接受但不同意。「你忙你的」是告诉你后果，不是给你许可。

判据：看这句话**是否比必要的说法更短、更客气、更完整**。三种异常都指向潜台词——比必要更短（「哦」），比必要更客气（「不用麻烦你了，谢谢」），比必要更完整（突然开始解释前因后果，通常是在铺垫一个要求）。

`unclear` 是合法答案。这时第 4 层要给出两种解读下都成立的候选——通常是一个只确认收到、不表态的短句。

**典型误判**：把「随你」判成字面同意。它字面是授权，实际是撤回参与。正确处理不是追问「你到底想怎样」，而是给一个具体方案让对方只需点头或摇头。

### 2 `intent` — 真实意图

六选一：

| 取值 | 含义 | 识别特征 |
| --- | --- | --- |
| `confirm_care` | 试探你在不在意 | 提到过去的事、时间、约定；句式是确认而非请求 |
| `vent` | 有情绪，要人接住 | 叙述委屈、抱怨第三方、用感叹或省略号 |
| `request_action` | 要一个具体动作或时间 | 出现时间词、地点、问句指向安排 |
| `seek_explanation` | 要一个解释 | 追问原因、复述矛盾点、「你当时为什么」 |
| `casual` | 闲聊 | 无诉求，分享、接梗、日常 |
| `close_topic` | 想收尾 | 短确认、总结句、「先这样」「睡了」 |

**典型误判**：把 `confirm_care` 判成 `request_action`。她说「你上次说的那个展，是这周还是下周」，字面在问日期，实际在问你记不记得。按 `request_action` 处理会得到一个准确但冰冷的日期，按 `confirm_care` 处理会得到一个「我记得，而且我已经安排好了」。

### 3 `danger` — 危险程度 0–9

不是情绪强度，是**处理错的代价**。

| 区间 | 含义 | 允许的策略 |
| --- | --- | --- |
| 0–3 | 安全，可推进 | 全部策略，含玩笑、邀约、调情 |
| 4–6 | 有张力，需谨慎 | 禁用玩笑与调情，允许实质内容与推进 |
| 7–9 | 高危，可能破裂 | 只允许 `hold` / `repair` / `care` |

判据：对方是否已经明确表达过不满或失望；这段关系当前是否处于可承受再一次失误的状态；这条消息如果不回或回错，是否有不可逆后果。

**典型误判**：把冷战的 `danger` 判低。冷战的特征是**没有消息**，而没有消息看起来像没有危险。实际上一段三天不回的关系，任何一句轻佻的话都可能成为终点。

### 4 `give_substance` — 该不该给实质内容

注意：这不是「该不该发消息」，是「这条消息里要不要有可执行的东西」。

要给的信号：对方在等安排、在验证承诺、在问具体的事。不要给的信号：对方在宣泄情绪、在测试态度、在闲聊。

**典型误判**：对方在哭，你给了一个完美的解决方案。方案是对的，时机是错的——情绪没被接住时，再正确的建议都会被读成「你不想听我说」。

### 5 `best_action` — 最佳动作

七选一：

| 取值 | 做什么 | 典型场景 |
| --- | --- | --- |
| `give_commitment` | 给一个具体、可兑现的承诺 | 对方在确认你记不记得 |
| `acknowledge` | 只确认收到了，不解释不承诺 | 对方在宣泄，还没到解决阶段 |
| `give_substance` | 给信息、方案、时间 | 对方在等安排 |
| `repair` | 认具体的那件事，给补救 | 自己确实做错了 |
| `advance` | 推进关系或落地下一步 | 互动良好，有窗口 |
| `hold` | 什么都不发，或发一句极短的 | 高危、对方在气头上、时机不对 |
| `close` | 干净收尾，不追加 | 对方明确要结束话题 |

`hold` 是最少被使用、也最常正确的动作。工具的价值不只在于「帮你回」，也在于「告诉你这条别回」。

### 6 `need` — 对方此刻需要什么

五选一：`care`（被看见）/ `clarity`（明确信息）/ `action`（有人做事）/ `space`（别打扰）/ `validation`（被认同）。

与 `intent` 的区别：`intent` 是对方在做什么，`need` 是对方缺什么。两者经常不一致——对方在追问细节（`intent = seek_explanation`），实际需要的是被安抚（`need = care`）。这时先满足 `need`，再满足 `intent`，顺序反了会吵起来。

### 7 `resolved` — 张力是否已解除

布尔值。`false` 时不允许推进，也不允许开新话题。看起来温和但仍在生气的对话，是最容易踩空的状态：你以为翻篇了，她只是在等你自己提。

## 二、关系阶段

`stage` 不是第八个问题，是判断的**背景参数**，影响其余七问的解读。

| 阶段 | 定义 | 判断影响 |
| --- | --- | --- |
| `stranger` | 刚加，未建立对话节奏 | 任何推进都显唐突，`advance` 权重最低 |
| `warming` | 有来有回，未线下 | 兴趣信号可读，但承诺类内容要轻 |
| `dating` | 约过 1–3 次 | 可直接邀约，可表达明确意图 |
| `couple_early` | 确认关系半年内 | 高频校准期，`confirm_care` 密集 |
| `couple_stable` | 稳定期 | 「想你了」可能是提要求的前置 |
| `repairing` | 冷战、分手边缘、修复期 | 全部策略降一档，`hold` 权重最高 |

同一句话在六个阶段可以是六种意思。这就是为什么没有阶段信息的通用模型，在这类任务上只能给出「安全但没有用」的答案。

## 三、三条候选

### 为什么是三条

一条是命令，用户只能接受或放弃；五条是负担，选择成本高于自己写。三条刚好覆盖「最保守 / 最实在 / 最主动」这一条决策轴，且允许第三条完全不同向。

### 策略定义

| 策略 | 定义 | 长度倾向 | 允许条件 |
| --- | --- | --- | --- |
| `minimal` | 只解决眼前问题，最低风险 | 极短 | 永远允许 |
| `care` | 只给情绪，不给方案 | 短 | 永远允许 |
| `hold` | 留白，或明确建议先别发 | 极短或零 | 永远允许 |
| `substantive` | 给足实质：时间、方案、具体的错 | 中长 | `give_substance = true` |
| `repair` | 认错 + 具体补救 | 中 | `danger ≥ 4` 或确有错 |
| `advance` | 推进或落地下一步 | 中短 | `danger ≤ 3` 且 `resolved = true` |

### 组合规则

- 必须至少有一条 `minimal` 或 `hold`。用户常常不是选最好的，是选敢发的。
- 三条不能同向。`substantive` + `advance` 同时出现时，必须有一条明显更保守。
- 三条长度必须拉开。全部落在 12–16 字，说明只换了措辞。
- `danger ≥ 7` 时只剩 `hold` / `repair` / `care` 三种可选。

### 目标锁定

写候选前先写一句目标：`让对方感到 X，同时我要 Y，不要 Z`。

例：`让她感到我记得这件事，同时我要把下周六定下来，不要显得像在弥补。`

这句话不进入输出，它的作用是防止三条候选漂移成三个不同目的。没有它，模型容易产出「一条安慰、一条邀约、一条讲道理」——这三条不是同一个问题的三个答案。

## 四、输出格式

```
她这句是在问你记不记得，不是真问时间。你只回「下周」等于没接住。

1. 下周六开幕
2. 下周六开幕 下午两点有讲解 我订两张
3. 下周六 我过去接你 中午先吃饭

选 2。别问「你怎么了」，她不想解释。
```

四条格式规则，每条都有理由：

1. **第一行是判断，一句话，说人话。** 用户最需要知道的往往不是「怎么回」，是「我有没有想多」。
2. **三条编号，不加引号。** 引号会让用户多一步删除操作，而在手机上选中再删是真实成本。
3. **最后一行是「选哪条 + 别做什么」。** 前者降低决策成本，后者防止最常见的反向操作。
4. **不输出 JSON、表格、分点分析、心理学名词。** 这些是引擎内部的表示，露出来就是把认知负担转嫁给用户。

全文控制在 120 字内。这个数字来自场景：地铁上、会议间隙、睡前躺着，单次注视时间在十秒量级。

---

## 五、三种模式的差异

| 用户说 | 走哪几层 | 输出 |
| --- | --- | --- |
| 帮我回这条 | 1→6 全部 | 判断 + 三条 + 提醒 |
| 他这句什么意思 | 1→2 | 只给判断，可含两种解读 |
| 我想这么回，帮我改得像人话 | 5→6 | 只给改写结果，不重写内容 |

第三种模式最容易被做错：用户已经决定说什么，此时再评判他的判断是越界。这时只做表达层的事——切碎、删句号、去掉书面语，内容一个字不动。
