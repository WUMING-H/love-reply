# 知识库

`references/kb/` 下 43 篇中文材料，是本项目的判断依据。这份文档说明它从哪来、怎么组织、什么时候读哪几篇，以及为什么绝大多数时候只读两篇。

---

## 一、来源与授权

43 篇全部来自开源项目 [goutoujunshi](https://github.com/shengjidaguai-china/goutoujunshi)（MIT License，Copyright (c) 2026 powerycy），**原样收录，未改动任何原文**。

保留了两级目录结构（`knowledge/` 与 `practical/`），因为原文之间有相对链接，打散会断链。版权全文见 `licenses/goutoujunshi-LICENSE`，归属声明见 `NOTICE.md`。

这套材料本身的质量是它被收录的唯一理由：它带证据分级，能分清哪些结论来自研究、哪些是流行说法、哪些只是经验策略。这在中文恋爱内容里很少见——大多数同类内容是结论先行，再倒找理由。

## 三、检索规则

路由数据在 `references/routes.json`，可读版在 `references/routes.md`（由数据生成，手改会被自检判红）。

**取路是一条命令，不是一张表。** 模型不再需要读路由表再自己去找文件：

```bash
python scripts/profile_tool.py kb --intent vent --stage couple_early --danger 5
# → references/kb/knowledge/07-沟通冲突与修复.md
#   references/kb/practical/为他人提供情绪价值：温暖且有效的回应指南.md

python scripts/profile_tool.py kb --intent vent --danger 8 --flag 危机
# → references/kb/knowledge/17-中国法律安全与危机转介.md（stop: true）
```

这样做不只是省事。以前表看漏一行、文件名被改、路径写错，都不会有人报错——**它只是少读一篇，而输出看起来一模一样**。命令化之后，输出就是那几条路径，取不到会立刻暴露。

三组审计分别盯三种漂移，任一条不干净 `validate` 就红：

| 审计 | 抓什么 |
|---|---|
| 声明 → 磁盘 | 路由指向的文件不存在（改名、误删） |
| 磁盘 → 声明 | 文件存在但谁也到不了（新加一篇忘了给入口） |
| `routes.json` → `routes.md` | 表和数据不一致（手改了生成的表） |

第三组是「派生物必须一致」的又一次应用：`SKILL.md` 与两个入口的关系也是这样。**两套不同的真相里，模型读到的永远是旧的那套。**

这里只说原则。

### 主键是 `intent × stage`

`intent` 决定读哪个领域，`stage` 决定读哪个强度。同一句「要不要见面」在 `warming` 阶段读邀约与第一次见面，在 `repairing` 阶段读冲突修复——不是同一批材料。

`danger` 是次级修正：高危时强制加入 07（沟通冲突与修复）或 15（分手与修复），并且屏蔽一切推进类材料。

### 上限三篇

不是成本考虑，是质量考虑。实测中读五篇以上会出现两个退化：

1. 输出变成综述句——「你需要先建立安全感，再逐步推进」，正确、无用、且不像人话。
2. 术语泄漏——「回避型依恋」「非暴力沟通」直接写进候选。第 5 层会拦，但拦下来就得重写，效率更低。

### 特殊场景优先于主路由

十四类场景（危机、操控、分手、投入失衡、拒绝、异地、性、钱与家庭、证据判断、夸、冷、轻松、截图、记忆）叠加在主路由之上，超过三篇时先砍主路由最后一篇——特殊情形比通用场景更该被看见。理由是这些场景的错判代价远高于普通对话：普通对话错了只是尴尬，这些错了可能有实际后果。

`危机` 是唯一例外：它**替换**全部篇目，只留 17 号那一篇，并置 `stop: true`。这时候只该有一件事要做，多给一篇都是在分散注意力。

## 四、知识不能进入文本

这是本项目最容易被违反、后果也最隐蔽的规则。

**表现**：候选里出现「我理解你需要安全感」「我们可以用非暴力沟通的方式聊聊」「这段关系现在处于权力不对等」。

**为什么必然发生**：模型看到上下文里有理论，会默认它应该被用上。这不是不听话，是合理归纳。

**为什么必须禁止**：用户在微信里不是在做咨询。任何术语都会立刻暴露「这不是他写的」，而这句话的目的是让对话继续，不是展示理解。

**验收标准**：把检索到的片段全部删掉，候选文本应该一个字都不变。

这条标准可以机械检查——同一输入跑两遍，一遍给知识、一遍不给，diff 输出。如果变了，说明知识被抄进去了。改动 `routes.md` 或候选策略后，建议跑一次这个对照。

## 五、什么时候不读

- 只有一两句的短对话，判断已经明确 → 直接写。
- `danger = 0` 的轻松闲聊 → 直接写。
- 用户说「我就想这么回，帮我润色」→ 跳过判断与检索，直接进风格层。
- 需要的是情绪承接而非方案 → 读一篇就够，`practical/为他人提供情绪价值` 通常是最优解。

省下的预算留给风格层。经验上，风格层对用户体验的影响大于知识层——用户能立刻感觉到「不像我」，但很难立刻感觉到「判断依据不够权威」。

## 六、扩充知识库

可以加，但有两条硬要求：

1. **必须标证据强度。** 参照 `knowledge/01` 的分级方式：研究支持 / 理论框架 / 流行说法 / 经验策略。没有分级的材料进来，会把整个库的可信度拉平。
2. **必须能落成策略。** 每篇都要能回答「读完它，第 4 层会做什么不同的事」。回答不了的，是读物，不是依据。

加完之后做三件事，缺一件 `validate` 就会红：

1. 在 `references/routes.json` 里给一个入口（`intents` 的矩阵、`flags` 的一条，或者 `reference_only` 并写清是哪篇文档指向它）。
2. 跑 `python scripts/kb_route.py render` 重新生成 `routes.md` 的表格块。
3. 跑 `python scripts/validate_skill.py`。

**每一篇都必须有归宿。** 既不在路由里、也没写进 `exclude` 说明理由的新文件，会被判为「谁也到不了」。这条故意做得严：知识库最容易的腐坏方式不是写错，是悄悄多出一批没人调用的文件，而体积和可信度照样在涨。
