# 架构

这份文档说明七步（0–6）是怎么划分的、每层的输入输出契约、以及为什么有些看起来可以合并的层必须分开。如果你只想用，不需要读它；如果你想改它，这是起点。

**给只读 `SKILL.md` 的人**：那里面把流程写成「判 → 写 → 过闸」三段，讲的是同一件事的另一种切法。对应关系是——`判` = 第 0–2 层（读档、读对话、判断），`写` = 第 3–5 层（取知识、写候选、改风格），`过闸` = 第 6 层（两道校验），第 7 层写回退为辅助动作。三段是给模型看的执行形状（少而明确，不容易跳），七层是给改代码的人看的契约（细而可测，每层单独失败）。两者不冲突，但改的时候要两边都对得上。

---

## 一、为什么是七步

最朴素的做法是一次调用：把聊天记录和「用我的风格回一句自然点的话」一起丢给模型。它也能出结果，但有三个绕不过去的问题：

**问题一：判错无人兜底。** 一句话到底是撒娇还是不满，模型在生成时顺手就定了，而定错的痕迹藏在文本里，用户只能感觉到「不对，但说不出哪不对」。判断必须显式化，才能被检查、被纠正、被回溯。

**问题二：知识会污染文本。** 读过依恋理论的模型，会把「回避型依恋」写进回复。这不是模型不听话，是它天然认为上下文里的东西都该用上。

**问题三：风格无处量化。** 「像他说话」在一次性生成里只是一个模糊形容词，没有人能验收，也没有人能回归测试。

第 1–6 层的本质是把这三件事拆开，让每一件都有独立的输入输出、独立的失败模式、独立的验收标准。

后来加的**档案**不属于这三件事，它是前置条件：给前三层提供这个具体的人的背景。它单独成一层（第 0 层），因为它的生命周期和其余六层完全不同——其余六层每次调用都重来一遍，档案是跨会话累积、会过期、需要复核的。

## 二、层间契约

```
                ┌──────────────────────────────────────────┐
   聊天记录 ──→ │ 0 档案     profile   （可选，有才跑）      │
                │   按对话检索：雷区、承诺、已知事实、认知     │
                └───────────────┬──────────────────────────┘
                                ↓ ≤6 条、380 字内的摘要
                ┌──────────────────────────────────────────┐
                │ 1 归一化   normalize                      │
                │   拆角色 · 去昵称 · 事实/推测/未知          │
                └───────────────┬──────────────────────────┘
                                ↓ { speakers, facts[], inferences[], unknowns[], stage }
                ┌──────────────────────────────────────────┐
                │ 2 判断     judge   （读 judge.md）        │
                │   7 问一次答完，禁止边判边写               │
                └───────────────┬──────────────────────────┘
                                ↓ { literal, intent, danger, give_substance, best_action, need, resolved }
                ┌──────────────────────────────────────────┐
                │ 3 检索     retrieve （kb 命令）           │
                │   intent × stage → 2–3 篇，路径直接可读    │
                └───────────────┬──────────────────────────┘
                                ↓ 知识片段（只进策略，不进文本）
                ┌──────────────────────────────────────────┐
                │ 4 生成     compose （读 compose.md）      │
                │   锁目标 → 3 条策略互异的候选              │
                └───────────────┬──────────────────────────┘
                                ↓ 3 × { strategy, text }
                ┌──────────────────────────────────────────┐
                │ 5 风格     style  （读 style-guide.md）   │
                │   语义冻结，只改表达                        │
                └───────────────┬──────────────────────────┘
                                ↓ 3 × { strategy, text' }
                ┌──────────────────────────────────────────┐
                │ 6 校验     verify （跑 style_tool.py）    │
                │   硬规则 + 风格指标                        │
                └───────────────┬──────────────────────────┘
                                ↓
                  一句判断 + 三条候选 + 一条「别做什么」
```

关键约束只有一条：**层与层之间只传结构化结果，不传自然语言推理过程**。第 2 层给第 4 层的是 `danger=5, best_action=give_commitment`，不是「我觉得她现在有点失望，所以你应该……」。前者可以被下一层机械执行，后者会被下一层当成风格参考抄进输出。

## 二点五、多轮：同一张图只走一半

上面这张图是**第一轮**。她回了话之后是另一条路径：

```
她的新回复 + 上一轮发出去的那句
        ↓
   判进退（withdraw / cold / engaged / unclear）
        ↓
   第 2 层判断（只需 best_action 与 need，不必重跑七问）
        ↓
   第 4–6 层：写一句 → 改风格 → 过闸
        ↓
   一句判断 + 一条候选 + 一条「接下来怎么接」
```

三处不一样，都有理由：

| 第一轮 | 第二轮 | 为什么 |
|---|---|---|
| 三条候选 | **一条** | 再摆三条等于把选择成本推回去；这时候要答的是「她这句怎么接」 |
| `danger` 是主要闸门 | **进退信号**是主要闸门 | 她已经在收的时候，问题不是危险，是不合时宜 |
| 输出「选哪条」 | 输出「发完就停」 | 她已经在这段对话里，多说一句只是多一次消耗 |

第 0 层（档案）与第 3 层（知识）照跑，但都不重来一遍完整检索——档案只查「她刚提到的东西」，知识只取她那句对应的一档（`intent` 六个里通常落在 `casual` 或 `vent`），不用重跑全部。

**第二轮最容易的退化是把它当成第一轮重来一次。** 这也是 `verify --then` 存在的理由：它不给「再想三条」留位置。

## 三、逐层说明

### 0 档案

职责：把「她是谁」和「我是谁、我要什么」压缩成几条能影响本次输出的背景。

- 输入：本次对话的一句话概括（用于检索）、`data/profile/{slot}.json`（她 + 目标）、`data/self.json`（我）。
- 输出：**不超过 520 字**的摘要，其中自我段单封顶 170 字；她那段最多 6 条、380 字。超出预算的部分不注入。
- 优先级固定：自我段（硬目标 → 软目标 → 底线 → 短板 → 能兑现）→ 阶段任务 → 相关条目 → 雷区与安抚器 → 临近或逾期承诺 → 过期提示。

自我段单独封顶，不是对称设计：它比「她」更重要（定方向），但也更容易变长（人会一直补充自己）。所以给它一个硬上限，防止它把「她」挤出去。

四条硬约束：

1. **不改 `danger`。** 危险等级只看当下这段对话。档案里写着「最近关系紧张」，这次她只是问晚饭吃什么，`danger` 仍然是 0。
2. **`low` 置信度的认知不得作为判断依据。** 只能用来生成"试探型"候选。
3. **不朗读。** 摘要给模型用，原文、条目 id、置信度标签都不出现在用户可见的输出里。
4. **硬目标只过滤，不打分。** 「不接受异地」不能被"部分满足"，命中触发词就删候选。

档案是自己一层的另一个原因：它是唯一**跨调用累积**的东西。其余六层每次都是从零开始，档案会过期、会互相矛盾、需要复核——所以它有独立的生命周期管理（`stale` / `accept` / `forget` / `goal done`）。

### 0.5 阶段卡

阶段在档案里存着，但它的作用不是背景信息，是**闸门参数**。所以第 0 层同时输出一张阶段卡：

```
stranger     允许 minimal/care             禁止 advance/repair/hold   细节 低   ≤24 字
warming      允许 minimal/care/substantive 禁止 repair/hold           细节 中   ≤34 字
dating       允许 minimal/substantive/advance  禁止 hold              细节 中高 ≤40 字
couple_early 五种都允许，hold 有条件                                   细节 高   ≤60 字
couple_stable 允许 minimal/substantive/care/repair/hold，advance 有条件 细节 高  ≤60 字
repairing    允许 hold/repair/minimal/care 禁止 advance               细节 低   ≤34 字
```

卡进第 4 层做策略白名单，进第 6 层做机械校验。**为什么是闸门不是权重**，见 `stages.md`。

### 0.6 默认画像

阶段卡之外，还有一层「默认画像」：目标是固定的人（ISFP + 巨蟹）时，无档案也能拿到
一组沟通先验，不用每次手动建档。它是第 0 层的一个分支，不是新的一层：

- **只调「怎么说」**：吃软不吃硬（别质问、别催表态）、慢热要安全感（先接情绪）、
  泛夸没用要具体（夸具体动作）。它落成 `PERSONA_HARD`（硬拦质问/催表态）和
  `PERSONA_SOFT`（软提示泛夸/讲道理）两组正则。
- **不下判断、不改 danger、不朗读人格标签**：画像的字一个都不进候选，也不用来
  「因为她是巨蟹所以会 X」。
- **档案优先**：档案里写了 `landmine`，画像就退场——雷区本身就是「怎么跟她说话」
  的定制，叠画像会打架。

为什么这层能存在：skill 从「跨用户通用」改成了「自己用」，目标从「一个函数对所有人
都正确」变成「对这一个具体的人最有效」。这是定位变化带来的收益，但代价是它假设了
「她是谁」——所以它必须被档案盖过，且永不参与判断。细则见 `references/persona-isfp-cancer.md`。

### 1 归一化

职责：把一段随意粘贴的文本变成可判断的结构。

- **拆角色**：`我：` / `她：` / `对方：` 都识，但昵称是自由的。**分不清时停下问一句「哪几条是你发的」**，不要猜。猜错角色会让后面每一层都反向，而且错误不可见——用户看到的仍然是一段通顺的话。
- **三栏拆分**：事实是能观察到的（「她回了一个字：哦」），推测必须标注主体（「她可能失望」），未知要显式留白（「她问展是真想去还是随口」）。绝大多数关系焦虑来自把推测当事实用，这一步是把它们物理隔开。
- **关系阶段**：`stranger` / `warming` / `dating` / `couple_early` / `couple_stable` / `repairing` 六档。判不出来时按对话里的既有证据取最保守的一档，并在输出里不做阶段相关的强假设。

### 2 判断

职责：把「该说什么」从直觉变成可枚举的取值集合。

七个问题一次答完，理由见 `flows.md`。这一层的产出必须是枚举值加数字，不是段落。允许的模糊只有一处：`literal` 可以标 `unclear`，这时第 4 层要同时准备两种解读下的候选。

`danger` 是全局闸门。它不是一个评分，是一个权限位：`≥7` 时第 4 层被禁止使用玩笑、邀约、调情三类策略，只剩稳住、补救、留白。

### 3 检索

职责：给策略提供依据，且保证依据不进入文本。

按 `intent × stage` 命中 2–3 篇，**不超过 3 篇**。上限不是成本考虑，是质量考虑：读五篇以上，输出会开始出现「你需要先建立安全感」这类综述句，而这句话对方看了只会更烦。

验收标准写得很硬：把检索到的片段全部删掉，候选文本应该**一个字都不变**。如果变了，说明知识被抄进去了。这条标准可以自动检查——同一输入跑两遍，一遍给知识一遍不给，比对输出。

### 4 生成

职责：在约束内出三个**真正不同**的选项。

先过阶段卡，把禁用策略剔掉；再锁目标，一句：`让对方感到 X，同时我要 Y，不要 Z`。前者定手段，后者定方向，顺序不能换——先写候选再套阶段，等于让模型写完再删，删不干净。

目标里的 Y 必须来自个人目标。缺了这一项，模型会稳定地优化「这条消息的效果」，而用户要的可能是「看清她怎么想」或「体面收尾」，两者的正解完全不同。

三条候选的策略必须互异，且必须覆盖至少一条低风险退路（`minimal` 或 `hold`）。这是因为用户的实际决策往往不是「哪句最好」，而是「我现在敢发哪句」。

自检三条：字数是否相近？风险是否一样？念出来语气是否一样？任一为是，说明只是换了措辞，要重写。

### 5 风格

职责：把「正确的意思」变成「他会打出来的字」。

**语义冻结**是这层的硬约束：时间、地点、承诺、认的那个具体的错，一个都不能丢。只允许改：长度、断句、标点、语气词、开场白、语序。

风格卡不存在时走冷启动，但**不允许阻塞当次输出**：先用安全默认（短、不加句号、无 emoji）出结果，末尾轻问一句校准。首次使用就被要求填五个问题，多数人会直接关掉。

### 6 校验

职责：把「像不像」从主观判断变成可回归的检查。

两道闸门，先内容后表达：

- **内容闸门（`guard`）**：踩底线（`limit` / `flaw` 的触发词）、违背硬目标、用了阶段禁用的策略、超出该阶段字数上限。命中即失败。
- **表达闸门（`check`）**：术语黑名单、AI 味短语、长度区间（按策略分档）、句号率、emoji 密度、短句比例。超限给具体数字和修改方向，不给评分。

顺序不能反。先查表达会把一条「说得很像他、但踩了他自己底线」的候选调到合格，那是把错误包装得更像对的。

连改两次仍不通过，采用未改写的版本。**宁可不像，不要为像而失真**——把「下周六下午两点」压成「周六见」是风格层的典型过度拟合，信息丢了，风格再准也没用。

## 四、上下文预算

Skill 的上下文是有限资源，主文件越长，留给对话的越少。当前分配：

| 文件 | 体量 | 何时加载 |
| --- | --- | --- |
| `SKILL.md` | 约 4.5 KB | 每次触发 |
| `references/judge.md` | 约 3 KB | 每次触发 |
| `references/compose.md` | 约 5 KB | 每次触发 |
| `references/stages.md` | 约 6 KB | 阶段判定、需要逐阶段说明时 |
| `references/self.md` | 约 7 KB | 建自我档案、写目标时 |
| `references/style-guide.md` | 约 4 KB | 有风格卡或需要冷启动时 |
| `references/profile.md` | 约 6 KB | 建档、改档、复核时 |
| `references/routes.json` | 约 9 KB | `kb` 命令背后的数据，模型不直接读 |
| `references/kb/**` | 416 KB | **按需 2–3 篇，永不整目录读取** |
| `data/profile/{slot}.json` | 不定 | **只经 `brief` 注入，她那段 ≤380 字** |
| `data/self.json` | 不定 | **只经 `brief` 注入，自我段 ≤170 字** |

`scripts/validate_skill.py` 会检查主文件是否超出预算，以及路由的三组一致性：声明的文件都存在、存在的文件都有归宿（路由或显式排除）、`routes.md` 与 `routes.json` 不漂移。断链的路由比没有路由更糟，它会让模型去猜文件名。

## 五、失败与降级

| 失败点 | 表现 | 降级策略 |
| --- | --- | --- |
| 角色分不清 | 无法判断谁说了什么 | 停下问一句，不猜 |
| 阶段判不出 | 输出泛化 | 取最保守档，不启用阶段假设；问一句「你们现在算什么状态」 |
| 阶段判错 | 方向整体偏移，且每步自洽 | `guard` 拦连带错误；建议 `init --stage` 固定下来 |
| 没有自我档案 | 只优化「效果」，方向可能不是他要的 | 静默跳过自我段，不追问 |
| 目标是硬目标但时机不对 | 用户想推，阶段不许 | 阶段优先，输出里说明「现在说会起反效果」 |
| 知识断链 | 路由指向不存在的文件 | 跳过检索，凭判断层直接写 |
| 风格卡缺失 | 输出是「正常人」而非「本人」 | 安全默认 + 末尾校准 |
| 档案缺失 | 输出缺具体性 | 直接跳过第 0 层，不向用户索要资料 |
| 档案过期 | 按半年前的判断给建议 | `stale` 提示复核；摘要里标注未复核 |
| 档案矛盾 | 输出在两种认知间摇摆 | 同主题录入时先提示删旧条目 |
| 校验连败两次 | 改不出合格句 | 用未改写的版本，附一句说明 |
| 命中危险内容 | — | 停止话术，转求助渠道（见 `safety.md`） |

设计取向很明确：**任何一层失败都要退化成「稍微平庸但可用」，不能退化成「报错」或「胡说」**。用户在地铁上，他没有耐心处理异常。
