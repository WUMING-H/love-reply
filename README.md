我们在聊天框里卡住的时刻，通常不是不知道该说什么，而是**不确定这句话到底是什么意思**。「哦」是收到了，还是不高兴了？「下周」是在问日期，还是在确认你记不记得？一旦判错，写得再漂亮的句子也只会把事情推远。

市面上大多数「AI 帮你回消息」跳过了这一步，直接生成一段温和、得体、情绪价值拉满的话。它读起来永远正确，也永远不像你——你会发「下周六开幕 我订两张」，它给你「我很重视这次约定，已经提前确认好时间了，希望你能玩得开心」。这两句话之间隔的不是文采，是**身份**。

这个项目做两件事：先用一套固定问题把局势判清楚，再把结论写回**你本人的说话方式**里去。判断解决「该说什么」，风格解决「这话像不像你说的」。前者错了全盘皆输，后者错了则一眼假。

它是一个 Skill，不是一个 App。没有后端、没有数据库、不用申请 API Key、不读取你的任何聊天软件数据——你把想回的那几行粘贴进来就行。

## 它能帮你解决什么

| 你正在面对的情况 | 它会给什么 |
| --- | --- |
| 盯着一条消息十分钟，删了三遍还没发出去 | 三条可以直接复制发送的候选，语气和长度都不一样，挑一条最像你的 |
| 不确定对方是不是不高兴了 | 一句话说清这句在问什么，纯字面还是带潜台词 |
| 想认错、想补救，又怕越说越糟 | 认错的正确颗粒度：认具体的那件事，不认人格，不附带解释 |
| 想把关系往前推一步 | 落地的邀约（时间、地点、你能兑现的方案），不是「有空一起吃个饭」 |
| 一直在照顾对方情绪，自己越来越累 | 判断这段投入是否对等，以及降级投入或体面退出的说法 |
| 每次都想「我怎么又这么说」 | 风格卡把它变成你的默认输出，不用每次手改 |
| 怀疑自己在被操控，或想操控别人 | 识别与替代方案，不给操控手段 |
| 遇到跟踪、威胁、自伤、暴力 | 立刻停止话术，转求助渠道 |

## 三个决定性的设计

### 零、先想起来（恋爱档案）

在判断之前还有一步：如果你建过档案，先取出与这段对话相关的几条——她明确说过的雷区、你答应过还没做的事、你还不知道的部分。

这一步看起来只是"记住了背景"，实际改变的是候选的具体程度：知道她不吃芒果，就不会给你一条约火锅的候选；知道你欠着一次看展，就不会建议你许一个新的周末。详见下面的[恋爱档案](#恋爱档案把你对她的了解变成判断输入)。

### 一、先判断，后表达

写候选之前，必须先把七个问题一次答完：这句话是不是纯字面、真实意图是什么、危险程度有多高（0–9）、该不该给实质内容、最佳动作、对方此刻需要什么、张力是否已经解除。不判断就写，等于猜；而中文的潜台词密度极高，猜错的代价通常是一条发出去就撤不回的消息。

判断里还有一维常被忽略：**关系阶段**。同一句「想你了」，在暧昧期是兴趣信号，在稳定期可能是要提要求，在冷战期则是递台阶。没有阶段基线，模型只能给一个平均值的答案，而平均值的答案对任何一种具体关系都是错的。

危险等级决定后面能做什么。`danger ≥ 7` 时只允许「稳住、补救、留白」，禁止玩笑和邀约——这是硬约束，不是建议。很多人就是在对方已经在崩溃边缘时开了个玩笑，然后失去了解释的机会。

### 二、像你，不像「一个好人」

这是本项目与同类工具最实质的差别，也是最容易被误解的地方。**目标不是「像人」，是「像你」。**

「像人」无法验收——一段通顺、温和、体贴的话就已经「像人」了，但它可能是任何一个陌生人说的。「像你」可以验收：把你发的五条和它写的五条混在一起，让熟悉你的人猜哪几条不是你写的，猜中率接近五成才算过关。

差距不在用词，在**长度**。真人微信消息的中位数是 8–18 个字，短句占四到七成；而大模型直接输出是 40–70 个字，短句比例接近零，还习惯在句末补一个句号。这个差距比任何词汇选择都显眼——只学词汇不学长度，写出来的是另一个人穿着你的衣服。

所以风格层的第一动作从来不是换词，是**切碎、删句号、去掉开场白**。度量由纯代码完成，不交给模型：模型数不出「你的句号率是 0.06」，让它估会给你 0.3 这种瞎猜的数，而 0.06 和 0.3 之间就是像与不像的距离。

```
输入（聊天记录）
 ├─ 0 档案       检索相关背景：雷区、承诺、你知道的事（有档案才有这步）
 ├─ 1 归一化     拆角色、去昵称、分「事实 / 推测 / 未知」三栏
 ├─ 2 判断层     固定 7 问 + 关系阶段，一次调用，输出结构化判断
 ├─ 3 知识层     按「意图 × 阶段」检索 2–3 篇，不做全库注入
 ├─ 4 生成层     先锁目标，再出 3 条策略互异的候选
 ├─ 5 风格层     按人设槽位改写成「你会打出来的字」
 └─ 6 校验层     硬规则 + 风格指标，双闸门
      └→ 3 条候选 + 一句判断 + 一条「别做什么」
```

## 一套可以直接调用的中文关系知识库

全套 43 篇中文材料，覆盖从吸引、暧昧、冲突到婚姻、法律与危机的完整链路。它不是一个「恋爱话术合集」，而是一套带证据分级的判断依据：能分清哪些结论来自研究、哪些只是流行说法、哪些是经验策略。

| 领域 | 主要内容 |
| --- | --- |
| 关系心理学 | 吸引与选择、伴侣回应性、社会交换、承诺与依赖、权力与压力、修复机制 |
| 情绪与人格 | 依恋类型、焦虑与回避、情绪调节、MBTI 的合理用法与局限 |
| 认识与约会 | 主动表达、第一次见面、体验设计、邀约、关系确认、在线约会与数字边界 |
| 沟通与冲突 | 接话、共情、赞美、拒绝、道歉、吵架、对话演练、三层话术编排 |
| 操控识别 | PUA 与经典社交体系的机制、证据与风险边界，以及低风险的伦理替代 |
| 同意与边界 | 持续同意、性沟通、身体自主、亲密协商 |
| 婚姻与家庭 | 婚前协商、共同财务、家务分工、双方父母、家庭生命周期 |
| 法律与安全 | 中国婚姻家庭法律、家暴、跟踪、诈骗、证据保存与危机转介 |
| 分手与修复 | 失恋、背叛、复合、信任重建、投入失衡与体面退出 |
| 证据与边界 | 证据分级、内容边界、什么情况下不该给建议 |

**每次只取 2–3 篇。** 塞满不是更准，是开始念经——读得越多，输出越像论文，越不像一句能发出去的话。而且知识只影响策略，绝不进入文本：依恋理论、非暴力沟通、情绪价值这些词一个都不许出现在候选里。验收标准很硬：把读过的知识删掉，候选应该一个字都不变。变了就是照抄。

## 一句话是怎么产生的

```text
聊天记录
  → 分清谁说的哪句（分不清就问，不猜）
  → 拆成事实 / 推测 / 未知
  → 七问判断 + 关系阶段
  → 按意图与阶段检索 2–3 篇知识
  → 锁定目标：让对方感到 X，同时我要 Y，不要 Z
  → 三条策略互异的候选（不是三段换措辞的同一句话）
  → 改写成你的说法（语义冻结，只换表达）
  → 硬规则 + 风格指标双闸门
  → 一句判断 + 三条候选 + 一条「别做什么」
```

三条候选必须真的不同：`minimal` 是最短、最低风险的退路；`substantive` 给足实质（具体时间、具体方案、认的那个具体的错）；`advance` 推进下一步；`care` 只给情绪不给方案；`repair` 认错加补救；`hold` 建议先别发。如果三条字数相近、风险相同、念出来语气一样，就是没写出来，要重写。

## 用法

装好之后，三种说法就够：

**一、帮我回这条**

```text
她：你上次说的那个展，是这周还是下周
我：下周
她：哦
```

得到的是：

```text
她这句是在问你记不记得，不是真问时间。你只回「下周」等于没接住。

1. 下周六开幕
2. 下周六开幕 下午两点有讲解 我订两张
3. 下周六 我过去接你 中午先吃饭

选 2。别问「你怎么了」，她不想解释。
```

**二、他这句什么意思**——只给判断，不给话术。适合你其实知道怎么回、只是想确认自己没想多的时候。

**三、我想这么回，帮我改得像人话**——跳过分析直接润色。你自己的草稿往往内容是对的，只是长了、书面了、加了句号。

**四、记一下**——把刚发生的事写进档案：「记一下，她不吃芒果」「记一下，我答应下月陪她回去」。一次对话最多问一次，你说不用就不再提。

输出刻意做得很短：全文 120 字内，第一行判断，三条编号不加引号（省掉你删引号那一步），最后一行告诉你选哪条、以及这时别做什么。不输出 JSON、不输出表格、不输出心理学名词——那些是引擎内部用的，不是给你在地铁上看的东西。

## 风格卡：让它真的像你

没有风格卡也能用，给的是「一个正常人会怎么回」；有了之后，给的是「你会怎么回」。

```bash
# 一行一条，只放你自己发出的消息，50–100 条起步
python scripts/style_tool.py profile --file 我的消息.txt --slot couple_early

# 校验一条候选是否符合你的风格（按策略分档卡长度）
python scripts/style_tool.py check --text "下周六开幕" --strategy minimal

# 记录你选中的那条、或你手动改成的样子
python scripts/style_tool.py feedback --slot couple_early --kind edited \
  --ai "周六下午我去接你" --user "周六 我过去"
```

`profile` 会算出长度分布、句号率、emoji 密度、短句比例、语气助词密度，并从「你从不做什么」反推禁用表：语料里从不出现 emoji，就写「不用 emoji」；从不加句号，就写「不加句号」。

**反推禁用比正面描述有用得多。** 模型很难执行「你要幽默」，但很容易执行「不许出现 emoji」。前者是软引导，靠运气；后者是硬拦截，100% 可执行。风格卡里真正起作用的是那份 `avoid` 列表，不是那段「你的风格简洁自然」的总结。

**没有语料时，回答五个问题就能建 v0：** 一般发几条、每条多长？句末加句号吗？用 emoji 吗，最常哪两个？生气时变长（讲道理）还是变短（冷处理）？安慰人是先讲道理还是先接情绪？

**按关系分槽位**（`couple_early` / `couple_stable` / `friend` / `work`）。不是为了精细，是为了防串味——对伴侣的撒娇语气拿去回同事，会出事。

反馈里最有价值的不是「选第 2 条」，而是「不像我，我会说 XX」。你的改法会直接进入样本库，成为下一次的参照。点选只能说明偏好，改写能说明差异，后者信息量大得多。

## 恋爱档案：把你对她的了解变成判断输入

风格解决「像不像你说」，档案解决「准不准」。没有档案，每次都要重新交代背景，模型只能给「一般人会怎么回」；有档案，它给的是「针对这个人、这件事」。

档案存在本地一个明文 JSON 里，分七类：

| 类型 | 存什么 | 例子 |
| --- | --- | --- |
| 事实 | 她说过的、发生过的，可核验 | 生日 11 月 27 日；九点下班是常态 |
| 认知 | **你的理解**，必须带置信度 | 她不喜欢被安排，替她做决定会被当成不尊重 |
| 未知 | 明确还不知道、别乱猜的 | 她问展是真想去，还是随口一提 |
| 雷区 | 一碰就炸的具体做法 | 她说累的时候讲道理 |
| 安抚器 | 实测有效的降火方式 | 带她吃那家牛肉锅，吃完就好了 |
| 承诺 | 你答应过、还没兑现的事 | 陪她看展，11 月 15 日前 |
| 事件 | 时间线上的节点 | 九月一起出差三天 |

七类里最能改变输出的是**雷区**和**承诺**：前者让它在你要哄人的时候不会递一条讲道理的候选，后者让它不会建议你许一个已经欠着的新承诺。

```bash
python scripts/profile_tool.py init --slot couple_early --alias 她 --stage couple_early

python scripts/profile_tool.py add --slot couple_early --kind landmine \
  --text "她说累的时候别讲道理"

python scripts/profile_tool.py add --slot couple_early --kind read \
  --text "她不喜欢被安排，替她做决定会被当成不尊重" \
  --confidence high --evidence "两次提议都被她说我自己来" --tag 边界

# 每次回复前取一段摘要（380 字内，直接进上下文）
python scripts/profile_tool.py brief --slot couple_early --query "她说今天好累"
```

**认知与事实必须分开，这是整套设计的核心。** 把推断写成事实之后就再也不会被质疑了——档案里写着「她不喜欢被安排」，半年后你还在按这句话行动，而它可能来自一次误会。

所以认知带三档置信度：`high` 可直接作为依据，`mid` 只调语气不下结论，`low` **不得作为判断依据**，只能生成一条去问清楚的试探型候选。`brief` 输出里低置信的会带问号：

```
认知?[低] 她可能已经在考虑分手
```

看到这个标记，正确做法不是围着「她要分手」设计话术，而是给一条能问出实情、又不带审问感的话。**它提醒你去看，不告诉你答案。**

档案还有一条硬边界：**不能改变危险等级**。危险只看当下这条对话——历史关系再紧张，她这次只是问晚饭吃什么，就是 0 分。

关系会变，所以认知会过期：

```bash
python scripts/profile_tool.py stale --slot couple_early --days 60   # 哪些太久没确认
python scripts/profile_tool.py accept --slot couple_early --ids r1   # 仍然成立
python scripts/profile_tool.py forget --slot couple_early --ids r3   # 过时了，删掉
```

一份放了半年不动的档案，描述的是半年前的一个人。按它给建议，比没有档案更糟。

`data/` 已在 `.gitignore` 里。风格卡、恋爱档案、反馈日志都只在你本机，不上传、不联网、不外发。删掉这个目录等于清空所有个人数据，Skill 会退回到安全默认值继续工作。

档案是明文 JSON，可以直接打开看、直接改。**不要存身份证号、住址、单位全称、病历**——判断不需要这些，泄露的代价却很高。要记地点就记「公司附近那家咖啡店」，别写楼层和工位。

## 设计原则

1. **先判断，后表达。** 判断错了，写得再好也只是把错误说得更动听。
2. **像你，不像「一个好人」。** 通用得体的回复是失败品，它的上限就是「不像你」。
3. **知识只影响策略，不进入文本。** 一旦出现术语，用户就要替我们翻译，那还不如自己写。
4. **度量交给代码，判断交给模型。** 数字由统计得出，语义由模型理解，两者不互相越界。
5. **只说你能兑现的话。** 候选里的时间、地点、承诺，必须是用户做得到的；不确定就标注出来让他确认。
6. **危险情境先保安全。** 跟踪、威胁、自伤、暴力不适用任何恋爱话术，这时候唯一正确的输出是求助渠道。
7. **关于她的判断，要标确定程度。** 事实可以直接用，推断只能说成推断。低置信的判断只能用来问，不能用来断定——档案不该成为偏见的固化剂。

## 它不做什么

- **不给「TA 爱不爱你」打分。** 这是伪科学，会把人推向错误决策。能判断的是行为和模式，不是心意。
- **不抓聊天记录。** 不做无障碍读屏、不解析第三方 App 数据库、不碰加密。粘贴一下不到五秒，封号和合规风险都不值得。
- **不代发。** 自动回复看着省事，实际会让人失去对关系的真实判断。
- **不给操控性建议。** 不制造焦虑、不冷处理施压、不伪装身份、不教人「测试」对方。
- **不微调模型。** 几百条语料训出来是四不像，改一次要重训。风格卡改一个 JSON 就生效。
