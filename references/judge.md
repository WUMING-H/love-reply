# 判断协议 · 七问

一次判完，输出 JSON 在内部用，**不要给用户看**。

## 中文陷阱（先记这几条，比什么都重要）

**这些几乎从不表示字面意思：**

| 表面 | 实际 |
|---|---|
| 你是不是忘了 / 那你说啊 / 你行 / 大忙人 / 呵呵 | 要求证明你记得、你在意 |
| 随便 / 你爱怎样怎样 / 我习惯了 / 没事 / 行吧 | 有事，是委屈不是结束 |
| 单字冷回（哦 / 嗯 / 好）且前文有你的敷衍 | 失望，不是同意 |
| 你忙你的 / 不用了 / 我自己可以 | 期待你坚持，测你态度 |

**这些才是真的收尾：** 好呀 / 知道啦 / 谢谢 / 那就这样吧 / 明天见 / 辛苦啦（带温度、语气正常）。

**硬规则**：分手、删好友、「别联系我了」一律判 `vent`，绝不是 `close_topic`。

## 七问

### 1 `literal` (bool)
**true**：直白的信息、提问或安排，无指责、试探、讽刺、暗示。
**false**：有潜台词——试探记不记得、讽刺、委婉抱怨、暗示、陷阱提问、裹着提问的指责、冷短句实则责怪。

判据：**把这句话交给一个刚认识你们俩的陌生人，他会按字面理解吗？** 会 → true。

### 2 `intent` (6 选 1)

| 值 | 含义 | 信号 |
|---|---|---|
| `confirm_care` | 试探你记不记得、在不在意 | 你是不是又忘了 / 那你说啊 / 你行 / 大忙人 |
| `vent` | 生气或委屈，要情绪被承认 | 指责、翻旧账、我习惯了 / 随便 / 行吧 |
| `request_action` | 真要一个动作/时间/承诺 | 明确时间地点，不是在试探 |
| `seek_explanation` | 要事实性解释 | 为什么 / 怎么回事 / 你说清楚 |
| `casual` | 闲聊打趣，无测试无冲突 | 语气轻松、有来有回、无诉求 |
| `close_topic` | 和平收尾 | 好 / 知道啦 / 谢谢 / 明天见 |

主要想验证你记得 → `confirm_care`（哪怕措辞像「你说啊」）。
主要想知道为什么 → `seek_explanation`。

### 3 `danger` (0–9)

| 分 | 场景 |
|---|---|
| 0 | 轻松聊天，无抱怨无试探 |
| 1 | 轻微打趣或小提醒，能一笑而过 |
| 2 | 温和抱怨，没火气，仍有温度 |
| 3 | 明显不快，提到被忽视，但仍给补救机会 |
| 4 | 讽刺、冷短回、「你行」，在试探，敷衍会升级 |
| 5 | 明确生气，指责你不听不在意，要真实回应 |
| 6 | 明显愤怒并归责，回错会吵架 |
| 7 | 最后通牒式警告，不愿再谈除非有改变 |
| 8 | 通牒已摆上桌（再这样就分手 / 今晚就投诉） |
| 9 | 已破裂：说结束了、让你别回、已删好友、正在爆发 |

**反向校准**：她已经真诚接受道歉或确认了愉快安排 → 按**降温后的当前状态**打分，不要按之前抱怨的峰值。

### 4 `give_substance` (bool)

问的是「下一条该不该包含实质内容」，不是「该不该发消息」。实质 = 认一个具体的错 / 给具体时间方案 / 解释你确实知道的事实 / 复述她想确认的内容。

**false**：她想让你复述的东西这段记录里没有（你只能瞎猜）· 她在试探而你真不知道 · 一句稳住的话就够 · 已收尾 · 少说更安全（通牒期、她说别回了）。

**true**：需要的事实、那个具体的错、那个时间地点已经在记录里，她在等这个。

### 5 `best_action` (7 选 1)

| 值 | 何时 |
|---|---|
| `check_history` | 她要你复述某件具体的事而你还没证明你记得。**此时别道歉、别编方案** |
| `apologize` | 已有明确的错或伤害。**不是**为了还没搞清的事泛泛道歉 |
| `give_commitment` | 她要具体的承诺、期限或安排 |
| `explain` | 要解释发生了什么，且不该以道歉或新方案开头 |
| `acknowledge` | 让她知道你听到了，不给事实、不道歉、不给方案 |
| `say_less` | 多说会过度解释、重启已收话题、或在通牒上浇油 |
| `make_plan` | 为非冲突请求（吃饭、见面）提议或确认安排 |

### 6 `need` (5 选 1，看最新一条)

`apology` 要道歉且没接受 · `action` 要具体动作/时间/承诺/复述 · `explanation` 要解释且没得到 · `care` 要证明你在意，是关注测试 · `nothing` 不需要更多了。

**硬规则**：真诚接受了（谢谢 / 收到了 / 没事了 / 过去了）→ 必须 `nothing`，哪怕之前想要行动。
**硬规则**：反讽的「我习惯了」「随便」「不想听」→ **不是** `nothing`。

### 7 `resolved` (bool)

true 仅当：本来无张力，或她明确接受、降温、重新开玩笑、说没事了、确认了愉快安排。
false：讽刺的「你行」、未被回应的试探、残留责怪、未撤回的通牒。

## 三个典型例子

**例 1｜「哦」不是结束**
```
她：你上次说的那个展，是这周还是下周
我：下周
她：哦
```
→ `literal:false, intent:confirm_care, danger:5, give_substance:true, best_action:give_commitment, need:care, resolved:false`
她给了具体问题，你只答两个字，没接住。**别问「你怎么了」。**

**例 2｜修复已完成，别按峰值判**
```
她：算了 我习惯了
我：我错了 我明天一定到
她：好呀 那明天见
```
→ `literal:true, intent:close_topic, danger:1, give_substance:false, best_action:make_plan, need:nothing, resolved:true`
第一句是反讽，但后两句完成了修复。**判当前状态，不判峰值。**

**例 3｜不知道就先去查**
```
她：你昨天说要跟我说的那件事是什么来着
我：啊？什么
```
→ `give_substance:false, best_action:check_history, danger:6`
`give_substance=false` 而 `check_history`——不知道就先去查，**别道歉、别编一个方案糊过去**。

## 生成前自检

1. 「哦」「嗯」「行吧」我是不是判成 `casual` 了？（多数不是）
2. 她说「没事」我判成 `nothing` 了？（反讽的「没事」是 `care`）
3. 她让我复述我不知道的事，我给出 `apologize` 了？（应该是 `check_history`）
4. 已完成修复的对话，我还在按峰值打 danger？
5. `give_substance=true` 时，那个事实/方案在记录里真的存在吗？不存在就是 false。
