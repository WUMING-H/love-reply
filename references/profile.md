# 恋爱档案 · 把「你对她的了解」变成可用的判断输入

档案不是聊天记录，也不是日记。它是**一份假设集**：你确认过的事、你的观察、你还不知道的事，以及几条改变回复方式的硬约束。

没有档案时，每次都要重新交代背景，模型只能给"一般人会怎么回"。有档案时，它能给"针对这个人、这件事"的回法——这两者的差距，比换一个更强的模型更大。

---

## 1 七类条目

| 类型 | `kind` | 存什么 | 例子 |
|---|---|---|---|
| 事实 | `fact` | 她说过的、发生过的，可核验 | 生日 11 月 27 日；在科技园上班，九点下班是常态 |
| 认知 | `read` | **你的理解与判断**，必须带置信度 | 她不喜欢被安排，替她做决定会被当成不尊重 |
| 未知 | `unknown` | 明确还不知道、别乱猜的 | 她问展是真想去，还是随口一提 |
| 雷区 | `landmine` | 一碰就炸的具体做法 | 她说累的时候讲道理 |
| 安抚器 | `soother` | 实测有效的降火方式 | 带她去吃那家牛肉锅，吃完就好了 |
| 承诺 | `promise` | 你答应过、还没兑现的事 | 陪她看那个展，11 月 15 日前 |
| 事件 | `event` | 时间线上的节点 | 九月一起出差三天 |

七类里最有价值的两个是**雷区**和**承诺**，因为它们直接改变候选文本，而不是提供背景。

- 雷区进了上下文，模型就不会在你准备哄人的时候给你一条讲道理的候选。
- 承诺进了上下文，模型就不会建议你说"我明天一定到"——除非你确实答应过。

---

## 2 认知与事实必须分开

这是整个档案设计里最重要的分界线。

```
事实：她这周回消息平均隔 4 小时（可核验）
认知：她最近工作压力大，回得慢不是冷淡（推断，置信中）
未知：她对我上周取消约会到底介意到什么程度（不知道）
```

**为什么必须分开**：把推断写成事实之后，它就再也不会被质疑了。档案里写着"她不喜欢被安排"，三个月后你还在按这句话行动，而这条结论可能来自一次误会。分开存，才有机会被推翻。

**事实的写法**：只写观察到的行为和时间。"她生气了"不是事实，"她回了一个字：哦，然后两小时没回"是事实。

**认知的写法**：可以写判断，但必须回答两个问题——证据是什么，有多确定。

---

## 3 置信度：三档，各有各的用法

| 置信度 | 含义 | 允许怎么用 |
|---|---|---|
| `high` | 多次验证，有具体证据 | 可以直接作为候选设计的依据 |
| `mid` | 有观察支撑，但样本少 | 可以用于调整语气与话题，不要据此下结论 |
| `low` | 只是感觉，或只有一次 | **不得作为判断依据**，只能生成"试探型"候选（问一句，而不是替她决定） |

标记方式：`brief` 输出里低置信认知带 `?`：

```
认知?[低] 她可能已经在考虑分手
```

看到这个标记，正确做法不是围绕"她要分手"设计话术，而是给一条能问出实情、又不带审问感的话。**低置信认知的作用是提醒你去看，不是告诉你答案。**

一条 `low` 的认知被验证两次之后，用 `accept` 刷新，或重新录一条 `high` 并删掉旧的。长期不动的 `low` 是档案里最危险的东西——它看起来像知识，实际是焦虑的固化。

## 4 注入规则

`profile_tool.py brief` 生成给模型看的那段，有硬预算：**总 520 字**，其中「我」那段最多 170 字，「她」那段最多 6 条、380 字。

优先级固定：

0. 「我」：硬目标 → 软目标 → 底线 → 短板 → 能兑现（没有自我档案就整段跳过）
1. 阶段任务（一句话，来自阶段卡）
2. 与本次对话相关的（按关键词检索，最多 6 条）
3. 雷区、安抚器（各最多 2 条，无论相关与否都带）
4. 逾期或两周内到期的承诺
5. 若有过期未复核的认知，末尾一句提示

为什么限这么死：档案进的是**每次调用**的上下文。塞 30 条进去，模型会把注意力摊薄到每条上，结果每条都用一点、每条都用不深。宁可这次只带最相关的 4 条。

「我」那段单独封顶，是因为它更容易变长——人会一直补充自己——而它一旦占满，真正针对这个人的信息就挤不进去了。

```
[我]
目标! 三个月内把关系明确下来（本阶段·推进）
底线 不接受异地，不为了恋爱换城市
短板 她一沉默就连发三条追问
能兑现 工作日只能八点后
[她·couple_early·自2026-03]
任务 把磨合期的分歧说清楚，不攒着
雷区 别在她说累的时候讲道理
有效 带她去吃那家潮汕牛肉锅，吃完她心情会好
承诺(2026-11-15) 答应陪她去看那个展
认知?[低] 她可能已经在考虑分手
```

`目标!` 带感叹号的是硬目标——候选不能违背，守门会拦。这段是给模型看的，**不要原样转给用户**。

## 5 怎么录入：不要一次问十个问题

档案是长出来的，不是填出来的。三种录入时机：

**一、用户主动说"记一下"。** 直接 `add`，不要追问更多字段。

**二、对话里出现了新事实。** 例如他说"她周四要去上海出差"，回完消息后问一句：要不要记进档案。**问一次就够，不要每次都问**。

**三、用户自己讲了一大段。** 拆成条目再入库，拆完给他看一眼：

```
记了三条：
· 事实：她过敏，不能吃芒果
· 认知：她跟你妈第一次见面不太愉快（置信中）
· 承诺：你答应下月陪她回去一趟
对吗？要不要改？
```

`prompts/profile-interview.md` 里有完整的建档访谈脚本，十来个问题，用于从零开始。**不要主动发起这个访谈**——先解决他当下要回的那条消息，等他愿意花时间了再说。

## 6 偏见防护

档案最大的风险不是记错，是**把一次误判固化成长期前提**。四种常见形态：

| 风险 | 表现 | 对策 |
|---|---|---|
| 确认偏误 | 只记符合已有判断的事 | 录入时问一句「有没有相反的 Observation」；`unknowns` 里保留反例 |
| 标签化 | 「她就是回避型」 | 标签不得入库，只存具体行为；行为变了标签就该变 |
| 过期 | 三个月前的判断还在用 | `stale` 列出 60 天未复核的认知，主动提示 |
| 自证预言 | 按「她要分手」行动，最后真分手 | `low` 认知不得作为设计依据，只能生成试探型候选 |

还有一条来自判断层的同理规则：**档案不能改变 `danger` 的打分**。危险等级只看当下这条对话，不看历史。历史糟不代表这次也在生气，历史好也不代表这次没事。这是档案唯一被禁止影响的地方。

## 7 复核与更新

```bash
# 哪些认知太久没确认了
python scripts/profile_tool.py stale --slot couple_early --days 60

# 确认仍然成立（刷新日期）
python scripts/profile_tool.py accept --slot couple_early --ids r1

# 承诺兑现后标记完成
python scripts/profile_tool.py accept --slot couple_early --ids p1

# 删掉过时或写错的
python scripts/profile_tool.py forget --slot couple_early --ids r3
```

关系会变。一段档案放了半年不动，它描述的是半年前的一个人——按它给建议，比没有档案更糟。

建议的节奏：**每次关系阶段变化时清一遍**（在一起、吵架、和好、异地），平时一个月看一次 `stale`。

同主题录入冲突时，脚本会提醒：

```
已有同主题认知：她不喜欢被安排…
若已改变，先 forget 旧条目，否则会互相干扰。
```

不要两条都留着让模型自己权衡——它会在两条之间摇摆，输出反而更糊。

## 8 隐私

- 全部存在本地 `data/profile/{slot}.json`，明文 JSON，可以直接打开看、直接改。
- `data/` 在 `.gitignore` 里，不会进版本库。
- `forget` 单条删除，`export` 导出成 Markdown 备份，删掉整个 `data/` 等于全部清空。
- **不要存身份证号、住址、单位全称、病历。** 判断不需要这些，泄露的代价却很高。要记地点就记"公司附近那家咖啡店"，不要写楼层和工位。

档案是给人用的，不是给人看的——它越像一份冷静的观察笔记，越有用；越像一份情感日记，越容易把你困在里面。
