# 风格指南 · 让他认出这是自己说的话

## 1 目标：像「他」，不是像「人」

大多数人做这件事的目标是「写得像人」，这是错的。
- 「像人」= 加语气词、加 emoji、随便一点 → 产出油腻的刻板模仿
- 「像他」= 符合他的长度、标点、用词、遇到这事时的反应方式

**长度是第一硬指标。** 真人微信中位数 8–18 字，短句（≤6 字）占四到七成；AI 直接输出 40–70 字、短句接近零。这个差距比任何用词差异都明显。

所以第一步不是改词，是**切碎 + 删句号**。

## 2 风格卡

位置：`%LOVE_REPLY_HOME%/style/{slot}.json`（默认 `<skill>/data/style/`）
`slot` 取 `couple_early` / `couple_stable` / `friend` / `work` / `stranger`。

**必须分槽位**，不是为精细，是为**防串味**——对女友的撒娇语气拿去回同事会出事。

```json
{
  "slot": "couple_early",
  "metrics": {
    "chars_p50": 11, "chars_p90": 34, "short_ratio": 0.58,
    "emoji_per_100": 1.4, "terminal_period": 0.06,
    "high_risk_particle_per_100": 0.9
  },
  "strategy": {
    "length": "很短，能五个字说完不写八个字",
    "punctuation": "几乎不用句号，问句也常不加问号",
    "anger": "生气时变短变冷，不解释不争吵，先沉默一阵再回一句短的",
    "comfort": "不讲道理不给方案，先顺着骂一句，然后直接约出来吃饭",
    "apology": "认错快但只认具体那一件事，不泛泛道歉，不说「对不起」",
    "humor": "自嘲 + 损人，不用网络梗",
    "avoid": ["不用 emoji", "不用叠字", "不用「呢/啦/呀」", "不主动说想你"]
  },
  "samples": {
    "comfort": ["她那人事儿真多 你别往心里去", "出来吃个饭？我请"],
    "conflict": ["行 是我没看到 我错了"],
    "casual": ["刚看到 咋了"],
    "advance": ["那周六下午三点？"]
  }
}
```

### 临场取样：用他这次贴进来的对话

最快的样本不是攒语料，是**他刚贴进来的这段对话**——里面本来就有他自己发的话。

```bash
python scripts/style_tool.py sample --file 他的发言.txt --slot couple_early
```

输入只有他自己发的消息，一行一条。截图先让宿主读出文字（多模态可以直接看，右侧气泡是他），非多模态就让他复制出来。输出是一份 JSON：

```json
{
  "n_messages": 6, "confidence": "低", "small_sample": true,
  "metrics": {"chars_p50": 6, "chars_p90": 8, "terminal_period": 0.0, "emoji_per_100": 0.0},
  "inferred_avoid": ["不用 emoji", "不用叠字", "不用「呢、啦、呀」", "不加句号", "不用「哈哈」"]
}
```

**样本少于 12 条时，只用 `inferred_avoid`，不用 `metrics` 定字数上限。** 原因是分布不成立：一段对话里的他，可能只是「她生气了所以他变短」。6 条消息算出的 p50 是这次的状态，不是他平时的长度。脚本会自动把这种卡标成 `small_sample`，`check` 看到这个标记就绕开统计值、改用绝对档位，但禁用项照旧生效。

**临场样本默认只在这次生效，不落盘。** 要存进风格卡得显式 `--save`；如果已经有语料卡（`source: "corpus"`），它不会覆盖，除非加 `--force`。理由一样：一段对话的权重不该盖过几十上百条的基线。

**隐私。** 截图里的头像、昵称、手机号、群名、时间戳都不进档案。样本文件用完即弃，别放在 `data/` 里。

### 冷启动：连样本都没有时问 5 个问题

**不要在第一次就阻塞着问。** 先用下面「安全默认」出结果，在末尾补一句：

> 顺带问一句，你平时发消息是偏短还是偏长？加句号吗？——校准一次能准很多。

用户答了，再落卡。要问的 5 个（按重要性排）：

1. **长度**：一般发几条？每条多长？（一条短句 / 2-3 条连发 / 想到就发一段）
2. **句号**：句末加句号吗？（从不 / 有时 / 总是）
3. **emoji**：用吗？最常用哪两个？
4. **生气时**：变长（讲道理翻旧账）还是变短（冷处理）？
5. **安慰人**：先讲道理给方案，还是先接情绪顺着骂？

### 安全默认（无卡时用这个）

```
短（8-16 字）· 不加句号 · 不用 emoji · 不用「呢/啦/呀」· 不用叠字
生气时简短冷静不解释 · 安慰时先接情绪不给方案
不用书面语连词（此外/总之/因此）
```

## 3 改写规则

输入是第 4 步产出的候选（语义正确、略显书面），输出是「他会打出来的字」。

### 三条铁律

**① 信息量不变。** 时间、地点、承诺、认的那个错，一个都不能丢，也不能新增。
可以删的：解释性从句、总结句、客套、铺垫、情绪铺垫。

**② 长度必须真的砍到位。** 给 8–16 字就真的砍到 16 字以内，不是「意思上压缩」。

**③ 不加文里没有的语气。** 卡说不用语气词就不加「呢啦呀」，说不用句号就一条都别加，问句也不加问号。

### 通用技巧：先砍，再改

长句一次改不到位，就分两步在脑内做：

```
砍（只删不加）：铺垫、解释、总结、客套 → 保留所有具体信息
改（只换说法不改长度）：省主语、用逗号代替「因为」、问句改陈述
```

「删」和「改」是两个不同的优化目标，混在一起会折中。

## 4 Few-shot（照这个感觉改）

**安慰场景**
```
原句：我理解你现在很难受，她那样说确实不太公平，你要不要先深呼吸一下，别太往心里去。
改成：
她那人事儿真多
出来吃个饭？我请
```
> 删了「我理解你」（AI 味）、删了「深呼吸」（陌生人建议）、把「别太往心里去」融进第一句、用他真说过的「我请」。44 字 → 17 字，信息没丢。

**冲突场景**
```
原句：这件事是我的问题，我没有提前跟你确认时间，导致你等了很久，我向你道歉，下次我一定会注意。
改成：
行 是我没提前说
下次我定好再告诉你
```
> 删「这件事是我的问题」（泛泛道歉）、保留具体那件事、「向你道歉」全删（真人不这么说）、拆两条（连发）、不加句号。

**推进场景**
```
原句：不知道你这周末有没有时间，如果有的话我们可以一起去看那个展览，你觉得怎么样？
改成：
周六下午 我去接你？
```
> 砍掉「不知道你有没有时间」的客套（AI 的礼貌惯性，真人直接给方案）、给具体时间、一个问号收尾。44 字 → 10 字。

## 5 什么算失败

| 失败 | 例子 | 错在哪 |
|---|---|---|
| 加语气词假装口语 | 行吧～那就周六呀 | 卡说不用「呀」，也从不加波浪号 |
| 加 emoji 假装活泼 | 周六下午我去接你😊 | 密度超标 3 倍 |
| 只删字不改结构 | 我没提前确认时间，下次注意。 | 还是书面语，只是短了 |
| 保留总结句 | ……总之你别多想 | 「总之」AI 味，「别多想」陌生人话 |
| 保留完整因果 | 因为我忘了所以你没等到 | 真人不说「因为所以」 |
| 过度口语化 | 害 这事儿整的 属实有点那啥 | 这不是他，这是东北网红 |
| 丢失信息 | 原句有「周六三点」，改完只剩「周末」 | 语义保真失败 |

## 6 连发的判断

人常连发 2–3 条。什么时候拆：

- 原句包含**两个独立动作**（认错 + 给方案）→ 拆两条
- 超过 `chars_p90 × 1.5` → 拆
- `burst ≥ 2` 且场景是 conflict / repair → 倾向拆

拆的顺序：**第一条给情绪/态度，第二条给事实/方案**。反过来显得冷。

不要为了像而硬拆。只发一条的人就发一条。

## 7 积累（让他越来越准）

每次用户点选或手动改，都记下来：

```bash
python <skill>/scripts/style_tool.py feedback --slot couple_early --kind chosen \
  --strategy minimal --ai "周六 我过去"

python <skill>/scripts/style_tool.py feedback --slot couple_early --kind edited \
  --strategy minimal --ai "周六下午我去接你" --user "周六 我过去"
```

`--strategy` 必须填，否则这条记录只能算「发生过一次」，算不出他在哪种策略上更舒服。

`edited` 比 `chosen` 更有价值——改前改后成对出现，是天然的偏好数据，改写后的句子还会进 `samples`。

**这份记录只影响排序。** `profile_tool.py prefs` 统计后给一句提示，`verify` 把它放在 `habit` 字段里；票数不到五票就不出声（三次里两次选 A，可能只是那天只有 A 能用）。它永远不会让一条被阶段禁用的候选通过——偏好是喜好，闸门是边界，两件事。

攒够 30 条同槽位样本后，重跑统计更新 `metrics`，并把 `strategy` 的变化给用户看一眼再覆盖。
