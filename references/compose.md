# 生成协议 · 三条候选

## 顺序

```
⓪ 读阶段卡与目标：阶段定手段，目标定方向
① 写目标（一句话，必须服从 ⓪）
② 写 3 条，策略必须真的不同
③ 机械守门：跑 guard，踩底线或踩阶段的重写
④ 自评：goal_fit 0-1、efficacy 0-1
⑤ 按 0.7 × goal_fit + 0.3 × efficacy 排序
```

**这一步不管风格。** 输出应该是准确、完整、略显书面的。风格交给下一步。

---

## ⓪ 阶段与目标先于一切

```bash
python scripts/profile_tool.py brief --slot couple_early --query "..."  # 阶段卡 + 她 + 我，一次拿全
python scripts/profile_tool.py goal list --slot couple_early            # 只看目标时用这条
```

`brief` 的前三行就是阶段卡：允许的策略、禁止的策略、细节密度、字数上限。
（只想要阶段卡也可以单独跑 `stage`，但主流程里不必多跑一趟。）

**阶段管手段，目标管方向。** 顺序不能换：

1. **硬目标先过滤。** 候选里出现硬目标的 `forbid` 词，直接删掉，不参与排序。
2. **阶段优先于目标。** 目标要求的手段被当前阶段禁止时，阶段赢。

```
目标：三个月内明确关系（想 advance）
阶段：repairing（禁 advance）
→ 不是放弃目标，是这次不说
→ 正确输出：先把上次那件事说清楚，说了才有下一步
```

唯一例外：目标是 `exit` 时阶段闸门放宽——你不需要维持关系，只需要把话说完整。

3. **软目标进打分。** `goal_fit` 的定义从「这条消息的效果」改成「这条消息对你目标的贡献」。

判断层说这条该 `acknowledge`，但你的目标是 `exit`，那 `acknowledge` 就该做成一条把话说完整的候选，而不是一条软化气氛的候选。**同样是 acknowledge，方向不同，写法完全不同。**

---

## ① 目标

格式固定：

```
让 {对方} 感到 {情绪目标}，同时 {我的诉求}，不要 {禁忌}
```

例：
```
让她感到「我记得这件事」并且愿意一起去，同时给出确定时间，不要追问她为什么只回「哦」
```

目标写不出来，说明还没判断清楚。回上一步。

目标里必须能看出个人目标的影子。如果括号里那句话在六种目标下都成立，说明你写的是通用目标，不是他的。

---

## ② 三种策略的准确定义

| strategy | 定义 | 何时必须有 |
|---|---|---|
| `minimal` | 最短，最低风险，一句话只解决眼前问题 | **永远有**。这是用户的退路 |
| `substantive` | 给足实质：具体时间、具体方案、认的那个具体的错 | `give_substance = true` 时 |
| `care` | 只给情绪价值，不给方案 | `need = care` 且 `give_substance = false` |
| `repair` | 认错 + 具体补救 | `need = apology` |
| `advance` | 推进关系或落地下一步 | `danger ≤ 3` 时 |
| `hold` | 留白：一句短的，或明确建议先别发 | `danger ≥ 7`，或 `give_substance = false` 且 `need = nothing` |

**注意**：`best_action` 是判断结论，`strategy` 是实现方式，不是一一对应。
`best_action = give_commitment` 可以做成 `substantive`（给时间），也可以做成 `advance`（给时间 + 邀约）。

---

## ③ 自检：三条真的不同吗

任一为「是」就重写：

1. 三条**字数**是否接近？（都差不多长 = 只在换措辞）
2. 三条**风险**是否一样？（efficacy 都在 0.85 以上 = 没有真正的备选）
3. 念出来**语气**是否一样？（同一句的不同说法 = 失败）
4. 有没有一条是凑数的？（用户不会选 = 失败）

---

## ④ danger 分档的硬约束

| danger | 允许 | 禁止 |
|---|---|---|
| 0–3 | 全部 | — |
| 4–6 | minimal / substantive / care / repair | 邀约升温类，但「给时间」可以 |
| 7–8 | repair / substantive（只给已承诺的事）/ hold | **任何玩笑、惊喜、升温** |
| 9 | hold | 只输出「先别发」或一句极短的，附求助渠道 |

`danger = 9` 时，最后一行必须包含：别连续追问、别反复道歉轰炸、别去找对方。

---

## ⑤ 不许替用户承诺

候选里的时间、地点、金额、行动，用户必须能兑现。

```
❌ 我明天请假陪你
✅ 我明天下午能空出来
```

**先查 `capacity`。** 自我档案里写着「工作日只能八点后」，候选就不能出现「下午三点我去接你」；写着「周末常加班」，就不能把周六当成默认空档。

不确定时用可替换的占位，并标注「需要你确认周六是否真的有空」。

宁可给一个待确认的方案，也不要给一个漂亮但做不到的承诺。这是这类产品最容易失去信任的地方。

---

## ⑥ 知识库的正确用法

知识用来**决定策略**，不是**写进句子**。

```
❌ 根据依恋理论，你可能属于焦虑型依恋，建议采用安全型沟通，表达需求而不指责。
✅ 我下周去接你吧，正好路上说
```

判断标准：**把知识片段删掉，候选一个字都不该变。**

常见照抄：把「非暴力沟通四步」写进建议、把「情绪价值」当话术模板、给用户贴依恋类型标签。
这些在最后一行可以化用一句（帮他理解），但候选文本里绝不能出现。

## ⑦ 典型输出（内部结构，不给用户看）

```json
{
  "goal": "让她感到我记得并且愿意去，给出确定时间，不追问她为什么只回哦",
  "candidates": [
    {"strategy": "minimal", "text": "下周六开幕 我订两张", "goal_fit": 0.72, "efficacy": 0.91},
    {"strategy": "substantive", "text": "下周六开幕 我查了下午两点有场讲解 不方便就周日下午", "goal_fit": 0.88, "efficacy": 0.85},
    {"strategy": "advance", "text": "下周六我过去接你 你挑晚饭", "goal_fit": 0.9, "efficacy": 0.7}
  ],
  "avoid": ["别再只回两个字", "不要问「你怎么了」"]
}
```

排序后给用户看的只有三行文本 + 一句建议。

## ⑧ 档案的三个用法

档案到这一层才真正产生价值：它让候选**具体**，也让候选**靠谱**。

**一、把通用建议换成具体的话。**

```
❌ 我给你带点吃的
✅ 下班给你带那家牛肉锅 你几点走
```

后者只有在你知道她公司在哪、爱吃什么、几点下班时才写得出来。这是 `facts` 的用处。

**二、承诺校验。**

写出任何带时间、地点、行动的候选之前，先看有没有未兑现的 `promise`：

- 已经答应「陪她看展，11 月 15 日前」还没做 → **不要**再建议"我下周带你去 XX"。先把旧的兑现，或者直接把这条承诺做成候选。
- 想建议超出他能力范围的承诺（请假、跨城）→ 标「需要你确认」。

**三、有雷区时换说法，不换策略。**

档案写着「她说累的时候讲道理会炸」，`care` 照样用，只是内容不能出现分析和建议。策略不变，表达绕开。

注意：**档案只在生成层起作用，不回头改判断层的结论。** 判断说 `acknowledge`，就不能因为档案里有"上次吵架"而改成 `repair`。

---

## ⑨ 细节密度：给多少具体信息，由阶段决定

「具体」不是越多越好。每个阶段有一个恰当的量，给多了和给少了都是错。

| 阶段 | 密度 | 一条候选里放几样东西 |
|---|---|---|
| `stranger` | 低 | 一个具体点就够。给多了像用力过猛 |
| `warming` | 中 | 一个具体点 + 一个退路。不要同时给三个备选时间 |
| `dating` | 中高 | 时间 + 地点，两样 |
| `couple_early` | 高 | 时间 + 地点 + 她的偏好 |
| `couple_stable` | 高 | 时间 + 地点 + 共同记忆（她上次说过的事） |
| `repairing` | 低 | 只认那一件事。**细节越多越像辩解** |

**最反直觉的是最后一格。** 修复期你说「我六点就出发了，路上堵了四十分钟，我真的不是故意」，她听到的是「他在证明自己没错」。这个阶段只需要一句「是我没安排好」，细节留到她问。

**验收方式**：跑 `verify`，看每条候选的 `anchors` 字段。

```bash
python scripts/profile_tool.py verify --slot couple_early \
  --candidate 'substantive:下班给你带那家潮汕牛肉锅 你几点走'
```

`anchors` 非空，说明真的接住了档案里的具体事实。`substantive` / `advance` / `repair` 三档若 anchors 为空，会提示"没接住任何具体事实"。

注意它查的是**连续两字重合**，不是单字。用单字时「下午三点去吃饭」会误命中「她不吃芒果」——共享「点」「吃」两个字，但那不是细节，那是巧合。
